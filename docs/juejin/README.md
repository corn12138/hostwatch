## 后面怎么写

- 有值得记录的进展再写一篇，不把提交记录逐条改写成文章。
- 写清楚为什么改主意、哪里踩了坑、最后凭什么判断做对了。没发生过的调试经历、对话、耗时和情绪不编。
- 有数字就交代版本、机器、测量方法和范围；预算、短时结果、长期验证分开说。
- 以开发者口吻写具体事情，少用宣传词，不把每篇都写成统一模板。
- 正文保留文章发生时的阶段边界。后续功能另写新篇；旧文有事实错误时修正并注明。
