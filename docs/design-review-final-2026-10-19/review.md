## 结论

**可以作为本轮原生开发依据。保留当前极简视觉方向，在实现时修正下述数据与交互语义问题。** 无需重新选择设计方案，也无需增加页面层级。

这一版已有首页、资源详情、处理方法、其他异常、进程查看、设置和反馈状态，以及浅色/深色、图表和状态组件说明。首页的一句结论、三条资源状态、必要时出现的一条建议，符合“普通人几秒内知道是否需要处理、先做什么”的目标。

本次实际打开设计页面与可点击原型，检查可访问性树并保存、回看截图；同时对照当前工作区的数据模型与告警实现。以下交互结论仅针对网页原型，不代表原生 AppKit 功能、真实系统工具启动或性能已经验收。没有重新运行当前源码的构建和测试。

## 实际走过的路径

1. **打开 / 关闭 / 再打开：** 点击原型菜单栏图标，面板实际隐藏并重新出现。外部日志宣称收起后继续采集，但网页日志不能证明原生采样行为。正常首页见 `01-home.png`。
2. **资源进入详情：** 实际点击内存行进入详情，看到用量、解释与历史图表，见 `02-memory.png`。处理器、磁盘详情在设计覆盖范围内，本次未逐一执行其全部交互。
3. **异常 → 处理方法 → 工具失败：** 严重状态下进入处理方法，切换模拟工具失败并点击打开活动监视器，观察到打开中、失败说明、手动路径和重试入口，见 `03-tool-failure.png`。系统动作仅为模拟。
4. **多项异常：** 切换多问题场景，点击“另有 2 项”，实际显示三组问题及对应严重程度，内存/交换合并展示，没有把 CPU 与磁盘问题丢掉。
5. **按需进程：** 更多菜单进入进程排行，先显示未读取，点击后经过加载，再显示五项结果，见 `05-processes.png`。本次执行了成功路径，未逐一执行空、失败与受限分支。
6. **暂停 → 改间隔 → 继续：** 暂停后操作变为继续；进入设置将 30 秒改为 5 秒，选中项与底部文字一致；恢复后原型日志显示建立基线，已有异常保留。没有据此确认真实计时器或速率重建。
7. **缺失 / 重试 / 恢复：** 部分缺失场景没有把交换未知当作零，深色见 `04-partial-dark.png`。采集失败后点击重试，恢复至速率预热，见 `06-retry.png`。恢复观察场景从 1/2 推进一个正常样本，变为 2/2 并显示恢复反馈。
8. **退出：** 从更多菜单退出后，原型菜单栏图标和面板消失，显示原型已退出的结束反馈，见 `07-quit.png`。原生进程退出码与残留进程尚待开发后验收。

这些问题可以在开发中直接修正，不需要把首页变成技术说明页。详细解释放到主动展开的详情或数据说明中。

## 原生实现边界

- 保持 Rust 核心 + AppKit 单进程；轻量原生浮层与图表。网页仅为视觉及交互参考，原型外层场景控制台、示例数据和模拟器不得进入产品。
- 当前源码已有公共 run-loop mode 采样、避免重复标题重绘、缺失 CPU 不误报正常、系统工具启动失败反馈。以工作区实际代码为准保留这些修复；早先审计中的问题不能未经复核重复列为当前缺陷。
- 收起停止不可见绘制，继续既定采样；显式暂停才停止采集；恢复建立新速率基线。按需进程扫描不得混入常规采样。
- 本轮补全必要页面及交互，不加入通知、登录启动、自动清理、结束进程、目录扫描、云端 AI、WebView 或 Windows 实现。
- 现有文字菜单的内存/CPU记录不是新浮层的验收证据。RSS ≤40 MiB 原目标尚未达成；physical footprint ≤40 MB 是待批准替代提案，不能自行改成已批准或已通过。
