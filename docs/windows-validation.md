# Windows 本机验证

日期：2026-11-07。Rust / Cargo 1.79.0，Windows x64；使用 Rust 自带 LLD 与项目内 Windows SDK / CRT 构建。没有修改全局工具链、系统环境变量或系统设置。

## 检查结果

- `cargo fmt --all -- --check`：通过。
- `cargo clippy --locked --all-targets -- -D warnings`：通过。
- `cargo test --locked`：67 个单元测试、3 个 CLI 集成测试全部通过。
- `windows/test-dashboard.ps1`：无窗口组件测试通过，覆盖脚本解析、真实指标绑定、四个导航按钮、异步分析、策略选择、导出 JSON 序列化及取消子进程。
- release CLI 与原生 .NET 桌面 EXE：构建并打包成功，静态 CRT。

## 实机检查

实际桌面窗口检查确认资源总览显示真实 CPU、物理内存、提交量、C 盘可用空间与进程排行。实测修复了 PowerShell 在大容量数值上选择 Int32 重载导致的显示错误。

导航、扫描、策略和取消通过无窗口组件测试验证。尚未人工点击完成保存文件对话框、托盘恢复与不同 DPI / 主题下的完整流程；导出序列化及退出清理逻辑已有组件验证。没有执行任何迁移或清理。

一次本机 C 盘只读扫描使用 30 秒上限：约 204,853 条目、174,668 个文件、20,959,866,248 bytes 已读逻辑长度，跳过 122 个重解析/云占位条目，56 个不可读条目。报告正确标记为不完整，不能据此推算整盘占用或安全释放量。扫描结果与路径未提交到 Git；仅保留在本机忽略目录中。

扫描和迁移测试包括：目录聚合、大文件排序、只读性、条目上限、非法根目录、目录联接循环、参数边界、单引号转义、禁止生成 `/MOVE` / `/MIR`、目标空间不足，以及扫描不完整时不宣称目标空间足够。Robocopy 仅生成含 `/L` 的预演命令。

## 使用边界

桌面版为 Windows 中文界面；没有实现 macOS 的 AppKit 界面、温度传感器或一键退出应用。Windows 持续告警与历史在 CLI `watch` 中可用，桌面显示当前采样建议。扫描结果是逻辑长度，硬链接可能重复计数，父子目录容量不能相加。Windows ARM64、企业策略环境与 macOS 变更后的构建未在本机验证。软件没有代码签名。
